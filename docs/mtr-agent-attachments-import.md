# Вложения и импорт спецификаций из чата

## Пользовательский сценарий

1. В виджете или `/mtr-analysis` нажмите кнопку вложения.
2. Выберите один синтетический файл спецификации.
3. Дождитесь статуса загрузки.
4. Отправьте файл без команды: агент покажет preview, распознанные строки, warnings и спросит, создать новую спецификацию, новую версию или отменить.
5. Для публикации дайте явную команду, например: `Загрузи как новую спецификацию «Ремонтная ведомость» для PRJ-021` либо выберите существующую спецификацию и попросите создать новую версию.

Чат принимает до четырёх вложений в одном сообщении, но публикация спецификации намеренно обрабатывает по одному файлу, чтобы не смешивать версии.

## Поддерживаемые форматы

Upload UI принимает `.xlsx`, `.xls`, `.csv`, `.txt`, `.pdf`, `.docx`, `.png`, `.jpg`, `.jpeg`, `.tiff`. Публикация разрешается только для `PARSED` файла с 1–500 валидными позициями и без блокирующих ошибок. Scan-PDF и неизвестное изображение получают `REVIEW_REQUIRED`; универсальный OCR не имитируется.

Минимальные поля позиции: код, наименование, положительное количество, единица. TXT/DOCX/text-PDF могут содержать четыре поля через `;` или `|`. Prompt injection и формулы внутри документа остаются неисполняемыми данными.

## Preview и публикация

Публичная карточка показывает не более 20 preview-строк, total/valid/invalid counts, warnings, target mode и ссылку на опубликованную версию. Сервер повторно валидирует файл при каждой попытке.

Публикация требует одновременно:

- `specification.upload` для чтения upload;
- совпадение владельца и активного проекта;
- `specification.publish` для целевой спецификации/проекта;
- однозначный target `NEW` или `NEW_VERSION`;
- явную publish-команду.

Idempotency связывает file ID, нормализованный instruction hash и target. Повтор того же запроса возвращает уже созданную версию и не создаёт duplicate. При новой версии предыдущая остаётся в истории.

## Аудит и ограничения

Preview и publish сохраняют безопасный audit без сырого содержимого файла. Identity, project, permissions и version из файла игнорируются. Внешняя запись в реальный Appius не выполняется: прототип публикует versioned запись в своей demo-БД.
