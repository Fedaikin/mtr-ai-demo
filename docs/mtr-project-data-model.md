# Модель бизнес-проектов и проектных остатков

## Два разных вида проекта

`AccessProjectScope` — техническая область RBAC. Она определяет membership, permissions и доступные source/catalog scopes. В demo-контуре это `demo-project-001`.

`BusinessProject` — предметный проект, о котором спрашивает пользователь: объект, очередь строительства, ремонтная программа или заказ. Он имеет код, название, даты, статус и связи со спецификациями. Несколько бизнес-проектов могут находиться внутри одного access scope. `specification.projectCode` — предметный атрибут, а не permission boundary.

Пользователь может передать название как подсказку, но сервер сначала ограничивает поиск текущим `TrustedRequestContext`, а затем разрешает сущность. ID, role, permission или scope из текста и файла не считаются доверенными.

## Dataset `universal-chat-v1`

| Сущность | Назначение |
|---|---|
| `business_projects` | Проекты, сроки и статусы внутри access scope |
| project/specification links | Связь всех 83 current-спецификаций с бизнес-проектами |
| position operational links | Связь 3 584 позиций с catalog/SAP material и проектом |
| specification intake | `RECEIVED`, `VALIDATING`, `ACCEPTED`, `FAILED` и timestamps |
| allocations/reservations | Уже распределённая потребность и резервы |
| inbound supplies | Подтверждённые поставки с датой прибытия |
| stock facts | Остаток, карантин, committed quantity и snapshot |
| movements | История расхода/прихода/корректировок для прогноза |
| reliability profiles | Отдельные факты MTBF и supply risk |
| chat attachments | Вложения, назначение и безопасный project link |

Migration `0008_universal_chat` добавляет эти таблицы и связи. `0009_chat_rbac_actions` расширяет метаданные подтверждаемых действий. Обе migration additive; `0000`–`0007` не переписываются.

## Формула проектного остатка

Версия правила: `project-material-balance-v1`.

```text
Свободно сейчас = max(0,
  остаток на складе
  − резерв
  − карантин
  − обязательства перед другими потребностями)

Свободно к дате потребности =
  свободно сейчас + подтверждённый приход до даты потребности

Потребность к дате =
  оставшаяся потребность проекта
  + прогноз расхода до даты
  + страховой запас

Дефицит = max(0, потребность к дате − свободно к дате)

Дозаказ = округление вверх до размера упаковки(
  max(0, дефицит − уже открытая закупка с поправкой на срок))
```

Все количественные входы — конечные неотрицательные целые числа. Размер упаковки — положительное целое. Резерв плюс карантин не может превышать физический остаток. Эти проверки выполняются до ответа агента.

## Защита от двойного распределения

Расчёт проекта использует allocation ledger. Остаток одного склада не может закрыть две позиции одновременно: после распределения доступное количество уменьшается. Альтернативные сценарии показываются как контрфактические планы и не изменяют основной ledger.

## Приём спецификаций и смысл «упало сегодня»

Lifecycle приёма хранится отдельно от версии спецификации. Фраза «упало сегодня» означает записи intake со статусом `FAILED`, timestamp которых попадает в календарный день `Europe/Moscow`. `RECEIVED` не считается ошибкой, а техническая задержка без terminal failure не превращается в «упало».

`ScenarioClock` использует фиксированный часовой пояс и явную границу `[начало дня, начало следующего дня)`, поэтому UTC-переход не сдвигает счётчик.

## Ограничения

Dataset синтетический. Он предназначен для проверки join, формул, пагинации и поведения агента, а не для оценки реального запаса. Реальные справочники единиц, договорные приоритеты, lead-time distributions и multi-echelon allocation требуют отдельного подключения и версии semantic layer.
